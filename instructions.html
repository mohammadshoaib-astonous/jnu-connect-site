Module 02

Build Instructions

Follow along step by step. Each section builds on the last — don't skip ahead if a term feels unfamiliar, ask your table before moving on.

Before You Start

Object = a category of data (like an Excel sheet). Field = a single column. Record = one row. Lookup = a link between two objects. Everything today is built with clicks — no code.

Setup Basics
1
Find the App Launcher
Locate the grid icon top-left — this is how you jump between apps and objects.
2
Open Setup
Click the gear icon top-right. This is where all "building" happens today.
Gear Icon → Setup
Objects & Fields
3
Create the School object
Create a new Custom Object, then add its four fields from the Data Model page.
Setup → Object Manager → Create → Custom Object
4
Create Department, Program, and Student
Repeat the same process for each object, in order — each one needs the last one to exist first, since it links back with a Lookup field.
5
Add Lookup relationship fields
On Department, add a Lookup field to School. On Program, add a Lookup to Department. On Student, add a Lookup to Program.
Object Manager → [Object] → Fields & Relationships → New → Lookup Relationship
Data Entry
6
Enter sample records
Use the real JNU sample data from the Data Model page — your own School, Department, and Program if you know them.
Validation Rule
7
Add a Validation Rule on Student
Prevent an Enrollment Year before 2007 (the year JNU was founded) or a future year.
Object Manager → Student → Validation Rules → New
List View
8
Create a filtered List View
Build a view like "CSE Students Only" or "2026 Enrollments" on the Student tab.
Flow (Automation)
9
Build a Record-Triggered Flow
Trigger: when a Student record is created. Step 1: update Status to "Enrolled." Step 2: send an email alert to the related Department's HOD.
Setup → Flows → New Flow → Record-Triggered Flow
Approval Process
10
Extend the Flow to submit for approval
When Status is "Pending Verification," auto-submit the record for approval instead of just notifying.
11
Create the Approval Process
Entry criteria: Status = "Pending Verification." Approver: the record's related HOD. On approval, set Status to "Enrolled"; on rejection, set it to "Rejected."
Setup → Process Automation → Approval Processes → New
Data Security
12
Build the Role Hierarchy
Director → HOD → Faculty. This is what lets the Approval Process route dynamically instead of to one hardcoded person.
Setup → Roles → Set Up Roles
13
Create demo Users and Profiles
Create 2–4 test users (Director, HOD, Faculty) and assign each a matching Profile and Role.
Setup → Users → New User
14
Assign a distinct Page Layout to HOD
Give the HOD Profile a layout on Student that surfaces the Approval History clearly.
Agentforce Demo
15
Create the JNU Connect Assistant agent
Topic 1: answer questions about Programs and Schools. Topic 2: let a student check their own enrollment status.
Setup → Agentforce Agents → New Agent
16
Test-drive the agent live
Ask it a program question, then an out-of-scope question, to see the guardrail decline gracefully.
